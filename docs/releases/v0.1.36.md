# Krill v0.1.36 릴리스 노트

v0.1.35 이후 변경은 다음과 같다. 이번 버전은 화면이 멈추는 문제를 다룬다. 실제 사용 중 멈춤이 줄었는지는 아직 측정하지 못했다. 대신 다음에 멈추면 원인이 앱 로그에 남는다.

**바로잡음:** v0.1.34 노트에 "화면 버퍼 대기, 화면 갱신 신호 끊김, 그리기 쪽 오류를 앱 로그에 남깁니다"라고 적었다. 실제로는 이 기록이 운영 로그 필터에 걸러져 한 줄도 남지 않았다. 이번 버전에서 고쳤다.

- 그리기 엔진(gpui)의 경고와 오류가 앱 로그(`~/Library/Logs/Krill/krill-app.log`)에 실제로 남는다. 다음 기록이 대상이다. 같은 경고가 쏟아져도 초당 20줄까지만 남는다.
  - 화면 버퍼 대기
  - 버퍼를 받지 못한 프레임
  - 이상이 있었던 1초의 프레임 요약
  - 화면 갱신 신호 끊김
- 화면 버퍼가 화면에 올라갔다는 신호가 늦어도 프레임을 오래 건너뛰지 않는다. GPU 작업이 끝난 뒤 그 신호를 50ms만 기다린다.
- 화면 버퍼를 받지 못한 프레임을 버리지 않고 다시 그린다. 재시도 간격은 50ms부터 시작해 최대 1초까지 늘어난다.
- 키를 입력할 때마다 화면 갱신 신호를 다시 만들던 동작을 없앴다.
- 꺼져 있는 원격 Mac에 창마다 따로 1분마다 ssh를 다시 띄우던 동작을 앱 전체에서 한 번으로 줄였다. 이 동작은 약 1분 주기로 반복되던 멈춤의 유력한 원인이다(추정).
  - 새로 연 창은 한 번은 직접 연결을 시도한다.
  - '다시 연결'을 누르거나 연결에 성공하면 꺼짐 판정이 풀린다.
- 사이드바의 원격 호스트 조회를 호스트별 전용 스레드로 옮겼다. 느린 ssh나 응답 없는 호스트가 앱의 공용 작업 스레드를 붙잡지 않는다. 1초 넘게 걸린 조회는 로그에 남는다.
- 창이 보이고 앱이 활성일 때 macOS의 App Nap과 타이머 묶기가 앱을 늦추지 않게 한다. 비활성이거나 창이 숨으면 해제한다.
- 멈춤 기록에 원인을 가를 정보를 더했다.
  - 감지가 늦어진 시간, 감시 스레드 자체가 늦게 깨어났는지(앱 전체 정지 의심), 앱이 활성 상태였는지를 함께 남긴다.
  - 창이 가려졌거나 디스플레이가 잠든 동안의 멈춤은 기록하지 않는다.
  - 스택 수집은 별도 스레드에서 한다.
- 앱 시작 로그에 버전, 실행 파일 경로, 상태 폴더를 남겨 운영 앱과 개발 빌드를 구분한다.
- 데몬(krilld)이 문제 상황을 로그에 남긴다.
  - 앱의 생존 신호가 2초 넘게 늦으면 기록한다.
  - 터미널 출력 기록이 100ms를 넘기면 기록한다.
- holder가 종료 신호(TERM·HUP·INT)를 받으면 보낸 프로세스와 세션 수를 로그에 남긴다. SIGKILL은 남길 수 없다.
- 자동 테스트가 운영 로그 폴더에 쓰지 않는다.
