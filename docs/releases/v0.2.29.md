# v0.2.29

- Usage polling no longer sends requests with an expired sign-in token. An account whose token has expired is shown as expired until its CLI refreshes it, and the token is re-read on every retry so the account recovers as soon as that happens. A failing account now logs one warning per failure streak instead of one every few minutes.
- Automatic account switching no longer gives up on a conversation that keeps printing output while it resumes, or on a transcript whose metadata is still being written.
- Account policy snapshots no longer leave temporary files behind after a failed save, and old leftovers are removed on startup.
- Test and verification runs no longer write into the real Krill log folder or the real error-reporting queue, so the production logs only show what actually happened on the machine.
- App launch no longer logs about twenty warnings for system fonts that are skipped on purpose, and skill synchronization racing between the app and the daemon is no longer reported as a failure; it retries on the next launch.
- The orchestration store can no longer fill up and reject every write. Under size pressure it now prunes finished and long-idle runs while keeping the current run, active workers, unanswered questions and coordinator bindings, and it tells you what to clean up if nothing safe is left.
- Leftover launch records of sessions that no longer exist are cleaned up when the daemon starts.
