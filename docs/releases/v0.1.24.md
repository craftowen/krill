# Krill v0.1.24 릴리스 노트

## 새 에이전트 세션

- 새 세션은 기본적으로 YOLO 권한으로 실행합니다. Claude Code·Codex 등 각 프로필의 승인 우회 인자를 적용합니다.
- `permission = "manual"`과 `yolo_mode = false`를 명시한 기존 설정은 유지합니다. 전역 권한 토글과 세션별 배지로 실행 권한을 확인할 수 있습니다.
- 기본 권한 적용과 데몬 재시작 후 세션 재개 동작의 회귀 검증을 보강했습니다.

## 야간 자동 릴리스

- 매일 한국시간 자정에 원격 dev와 main을 고정해 검증·배포하는 예약 실행기를 추가했습니다. 예약 등록과 상태 조회는 `packaging/README.md`에 설명합니다.
- 예약 실행은 Orca의 일반 셸에서 수행하며 원본 개발 체크아웃과 이미 진행 중인 릴리스를 분리합니다.
- 전체 검사·메모리·세션 생존 검사와 Windows·Linux 네이티브 빌드를 통과한 동일 커밋을 공식 게시 경로로 배포합니다.
- 빌드 전용 네이티브 CI와 검증된 자산 반입을 지원하고, 기존 태그·릴리스 덮어쓰기와 유료 VM 실행은 허용하지 않습니다.

## 모바일

- 실행 중인 PWA가 연결한 데스크톱과 호환되는 새 화면을 확인하고, 파일·해시·캐시 준비를 마친 뒤 안전한 시점에 갱신합니다.
- 갱신 기능을 지원하는 버전 사이에서 인증·현재 화면·채팅 초안·터미널 입력 버퍼를 같은 탭에 보존합니다. 한글 입력·전송·사진 처리 중이거나 전송 결과가 불확실하면 전환을 미룹니다.
- 호스트를 바꾼 뒤 이전 호스트의 초안이나 늦게 처리된 사진·입력이 새 호스트에 섞이지 않도록 보완했습니다.
- 프로젝트 목록에 좌우 여백을 넣고 하위 작업 공간 행을 들여써 목록 계층을 구분합니다.

## 원격 Krill 연결

- 앱 시작 시 `LinkHosts` 공유 싱글턴이 구 명칭(`mk-link`) 대신 `krill-link` 헬퍼 경로(`krill_app::hosts::link::executable()`)를 사용하도록 수정해, 설정 페이지에서 짝짓기에 성공한 뒤에도 사이드바·세션 연결이 실패하던 문제를 해결했습니다.
- 원격 Krill(`iroh:...`) 호스트의 재연결·재짝짓기 시 이전 오류 상태를 지우고 즉시 `krill-link connect` 터널을 재기동하도록 보완했습니다.
- 사이드바 원격 호스트 폴링이 느리거나 오프라인인 다른 호스트에 가로막히지 않고 호스트별 응답 즉시 상태를 갱신하며, 새 호스트 등록 시 폴링을 바로 다시 시작합니다.

## 터미널 스트림 정체 복구 및 UI 멈춤 진단

- `krill-holder`가 소유한 세션은 그대로 보존하면서, 응답 확인(ACK)이 멈춘 개별 UI 소켓만 재연결해 미확인 입력 중복 전송 없이 정체된 터미널 스트림을 자동 복구합니다.
- 독립된 UI 감시 스레드를 통해 macOS 메인 스레드가 멈출 때 상한이 적용된 로컬 스택 샘플을 기록하도록 진단 기능을 보강했습니다.

## 에이전트 오케스트레이션 및 스킬 자동 동기화

- 오케스트레이션 스킬을 앱·CLI·계정별 에이전트 준비 과정에서 자동 설치·갱신하며, 작업 분해·독립 검증·증거·재개 지침을 보강했습니다.
- `agy` CLI 전용·호환/계정 경로와 워커 실행 계약을 지원하고, 미지원 실행 옵션 및 잘못된 완료 보고는 거부합니다.

## 릴리스 검증

- 후보의 같은 커밋에서 성공한 Linux·macOS 필수 검사를 확인한 경우 main에서 그 결과를 재사용합니다. 증거가 없으면 전체 CI를 실행하며, 플랫폼·툴체인별 의존성 캐시를 사용합니다.
- 전체 검사·Windows clippy·메모리·실제 앱과 데몬의 세션 생존 검사를 통과한 출고 바이너리를 서명된 증거와 함께 고정합니다. 서명 번들도 원본과 대조하고 실제 실행·세션 생존을 확인합니다.
- 게시 뒤 태그·다운로드 파일·업데이트 서명을 다시 확인합니다. 취소와 재개, CI 재시도 및 게시 응답 유실 시에도 기존 태그·자산을 덮어쓰지 않습니다.
