# Computer-use v2 변경 안내 (개발 중)

이 문서는 개발 중인 `computer/2` 계약의 변경 사항이다. 설치된 Krill의 지원 범위는 `krill computer capabilities --json`과 같은 실행 파일의 `krill skills get computer-use`로 확인한다.

## 기존 호출을 옮길 때

- JSON 관찰은 기본적으로 압축 표현을 반환한다. 전체 트리가 필요하면 `--format full`을 지정한다. 스크린샷은 `--screenshot`으로 요청하며, `--no-screenshot`도 계속 지원한다.
- 관찰 결과의 `snapshotId`와 참조를 함께 사용한다. 참조 번호를 새 관찰의 같은 번호로 자동 교체하지 않는다. 참조는 120초 뒤 입력에 사용할 수 없으며, 서로 다른 부모 프로세스에서 실행한 명령은 캐시를 공유하지 않을 수 있다.
- `ok: false`인 동작 결과는 JSON 출력과 함께 비정상 종료 코드를 반환할 수 있다. 종료 코드만 보고 입력을 재전송하지 않는다. `delivery`, `observation`, `verification`, `cleanup`을 각각 확인한다. `submitted`는 앱의 업무 완료를 뜻하지 않는다.
- AX 동작 뒤 실패하거나 응답이 유실되면 다른 입력 방식으로 자동 대체하지 않는다. `unknown`이면 화면을 새로 관찰한 뒤 다음 동작을 판단한다.
- 붙여넣기는 읽을 수 있는 클립보드 형식을 4MiB까지 보존한다. 대상의 전체 값이 기대한 편집 결과와 일치해야 소비를 확인한다. 사용자 복사와 충돌하거나 소비를 확인하지 못하면 복원이 불완전할 수 있다. 이전 클립보드 내용은 결과에 포함하지 않는다.

`--element-index`, `--mouse-button`, hotkey의 `--key` 등 기존 별칭은 유지한다. 새 실패 판정과 기본 출력 변경은 호출 측에서 처리해야 한다.

## 좌표와 캡처

입력 좌표는 데스크톱 논리 좌표다. 이미지 픽셀을 그대로 전달하지 않는다. 측정 가능한 캡처는 실제 PNG 치수, 논리 경계, `mapping.imageToDesktop`, 별도 관찰·캡처 시간과 geometry 증거를 제공한다. 매핑을 입증하지 못하면 이를 제공하지 않으며, 지원하지 않는 배율·회전·여러 디스플레이에 걸친 캡처를 추측으로 변환하지 않는다. 오래된 이미지나 바뀐 창의 좌표는 새 관찰로 대체한다.

`valueSettable`은 해당 관찰에서 확인한 AXValue 쓰기 가능 여부다. 값이 없으면 확인하지 못한 상태이며, `false`로 추정하지 않는다.

## 실험용 네이티브 경로

기본 명령은 JXA를 사용한다. `krill computer serve --experimental`은 한 stdio 세션에서 별도 네이티브 실행기를 사용하는 선택 경로이며 MCP 2025-11-25를 지원한다. 실제 권한·업데이트·장애·자원·성능 채택 검증을 모두 통과했다고 가정하지 않는다. 지원 동작은 `computer_session`과 `tools/list`를 확인한다.

선택적 `format: "delta"`와 `baseSnapshot`은 새 `observe` 결과의 표현만 줄인다. 먼저 전달받은 완전한 `full` 결과가 필요하며, 매번 실제 새 관찰을 수행한다. 기준 결과가 없거나 부분 관찰이면 같은 새 관찰의 compact 결과와 명시적인 사유를 반환한다. `removed`는 이전 표시 키가 새 표현에서 빠졌다는 뜻이며, UI 요소의 소멸을 검증한 결과가 아니다. 새 입력에는 새 결과의 스냅샷과 참조를 사용한다.

변경이 많아 델타보다 전체 표현이 작으면 새 전체 결과(`data.format: "full"`)와 `delta_not_smaller_than_full` 사유를 반환한다. 같은 새 관찰을 사용하며, 이 전체 결과를 다음 델타의 기준으로 사용할 수 있다.
