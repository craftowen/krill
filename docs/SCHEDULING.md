# 예약 자동화 (MK-101)

`krill schedule`은 상태 디렉터리의 `schedules.toml`을 편집하고, krilld는 앱이 닫힌 상태에서도 cron에 맞는 새 holder 세션을 만든다. 등록 시 데몬도 자동으로 기동한다.

```sh
mk schedule add greeting --cron '*/15 9-17 * * 1-5' \
  --cwd "$PWD" --prompt '안녕하세요 $(이 문자열은 그대로 전달됩니다)' \
  -- /bin/echo
mk schedule list
mk schedule runs
mk schedule rm greeting
```

`--` 뒤는 실행 파일과 고정 인자다. 프롬프트는 **마지막 인자 하나**로 전달하며 셸 코드로 평가하지 않는다. 에이전트를 실행하려면 해당 CLI의 비대화형 실행 인자를 명령에 명시한다. 예약 실행이 권한 우회 인자를 자동으로 추가하지는 않는다. `--cwd`를 생략하면 등록 당시의 현재 디렉터리를 저장한다. ID는 ASCII 영숫자, `_`, `-`로 구성하며 중복 등록은 거부한다.

cron은 **UTC 기준 5필드** `분 시 일 월 요일`이며 숫자, `*`, 쉼표 목록, 범위, `*/n`·`a-b/n` 간격을 지원한다. 요일은 일요일 `0` 또는 `7`이다. 일과 요일이 모두 제한되면 둘 중 하나가 맞을 때 실행한다. 이름·별칭·초 필드·RRULE은 지원하지 않는다. 예제의 시각은 UTC이며 한국 시각으로는 9시간을 더한다.

데몬은 시작할 때와 이후 매 분 현재 분만 평가한다. 실행 중 설정 변경은 다음 분부터 반영한다. 잠자기·데몬 중단으로 지나간 분은 재실행하지 않으며, 같은 분에 재시작하면 아직 기록하지 않은 예약만 실행한다. 시스템 시계가 뒤로 이동하면 해당 데몬이 이미 평가한 분을 다시 실행하지 않는다. 긴 작업은 다음 예약과 겹칠 수 있으며 기존 세션 상한을 따른다.

`krill schedule runs`는 `schedule-runs.jsonl`과 직전 회전 파일을 JSONL로 출력한다. 각 행에는 예약 ID, Unix epoch 이후 UTC 분 번호, 단계와 세션 ID가 있다. `started`는 실행 전 디스크에 확정한 시도, `spawned`는 holder가 프로세스를 생성한 상태, `failed`는 세션 생성 실패다. `finished`에는 holder의 **원시 wait 상태**(`status`)를 저장한다. `spawned`만으로 프롬프트 처리 성공을 뜻하지 않는다. 종료 상태와 PTY EOF가 모두 확인되면 다음 분 점검 때 기록하고 예약 세션을 정리한다. 루트 프로세스가 끝나도 자식이 PTY를 사용 중이면 유지한다. 실행 중에는 일반 `krill ls/read/attach`로 세션을 볼 수 있고, 정리 뒤 출력 세그먼트는 기존 보존 정책을 따른다.

실행 전 기록과 실제 프로세스 생성 사이에 데몬이 죽으면 `started`만 남을 수 있다. 중복 실행을 피하기 위해 이런 불확실한 시도는 자동 재시도하지 않는다. 기록 쓰기에 실패하면 새 작업을 실행하지 않는다. 잘린 마지막 JSON 행은 다음 기록 전에 버리고, 완전한 행의 손상은 오류로 처리한다. 기록에는 프롬프트와 명령을 복제하지 않는다. 파일은 0600, 새 상태 디렉터리는 0700이며 설정은 잠금 아래 원자 교체한다. 설정은 최대 64개·256 KiB이고 기록은 1 MiB마다 한 벌을 회전하여 직전 한 벌만 보관한다. 장기간 중단·시계 변경·재부팅에 걸친 exactly-once 실행은 보장하지 않는다.
