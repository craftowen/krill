# 깊은 모듈 설계 기준서 (Deepening Reference)

이 문서는 [design.md](../playbooks/design.md) 실행 시에만 로드한다.

## 1. 깊은 모듈 판정 (Ousterhout 기준)

- **깊은 모듈 목표**: 외부에 노출하는 함수 시그니처, 설정 인자, 상태 전이 수는 최소화하고 내부에서 처리하는 복잡도와 불변 조건 보장은 최대화한다.
- **얕은 래퍼 제거(Deletion Test)**: 호출자가 1곳뿐인 패스스루 래퍼, 인자를 그대로 전달만 하는 중간 계층, 내부 구현 구조를 그대로 노출하는 데이터 전달 객체는 병합하거나 삭제한다.
- **2-어댑터 이음매 규칙(Two-Adapter Seam Rule)**: 실제 어댑터가 2개 이상 존재하거나 테스트 경계 교체가 필수인 지점에만 추상 인터페이스를 둔다. 단일 구현체 위에 미래 대비용 인터페이스를 미리 얹지 않는다.

## 2. 의존성 4분류와 테스트 전략

설계 대상이 건드리는 모든 의존성을 아래 4가지 중 하나로 분류하고 경계 교체 전략을 고정한다.

1. **In-process (순수 메모리/도메인 로직)**: 목(mock)이나 스텁을 절대 쓰지 않고 실제 함수와 데이터 구조에 대해 직접 행동 테스트를 작성한다.
2. **Local-substitutable (파일시스템, SQLite, 로컬 프로세스, Git)**: 임시 디렉터리나 인메모리/임시 SQLite 인스턴스로 실제 엔진을 구동해 검증한다.
3. **Remote-owned (자사 API, 제어 가능한 워커/서비스)**: 얇은 포트 인터페이스로 감싸고 계약 테스트(요청 페이로드 및 응답 스키마 검증)와 인메모리 페이크 어댑터를 쌍으로 둔다.
4. **True-external (외부 결제망, 제3자 SaaS, OS 화면 자동화)**: 최외곽 경계 어댑터 한 파일로 격리하고 타임아웃, 멱등성 키, 명시적 실패 타입만 계약으로 고정한다.

## 3. 경계 교체형 테스트 기준

- 내부 private 헬퍼 호출 횟수나 호출 순서를 단언하지 않는다.
- 모듈의 공개 진입점에 구체적 입력을 넣고 반환값, 외부로 기록된 상태, 경계 어댑터가 관측한 페이로드만 단언한다. 내부 구조를 통째로 리팩터링해도 테스트를 한 줄도 고치지 않고 통과해야 합격이다.
