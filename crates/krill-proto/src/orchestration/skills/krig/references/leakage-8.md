# 벤치마크 및 평가 8대 검증 누수 점검표 (Leakage-8 Audit)

이 문서는 [verify.md](../playbooks/verify.md)에서 성능 수치, 정확도 평가, 벤치마크 개선을 검증할 때만 로드한다.

1. **평가셋 오염(Dataset Contamination)**: 테스트 픽스처나 정답 케이스의 문자열/분포를 코드의 하드코딩 규칙이나 정규식에 그대로 베껴 넣었는지 확인한다.
2. **하네스 변경 동시 커밋(Moving Goalpost)**: 성능/점수 측정 스크립트와 피측정 구현 코드를 같은 커밋에서 함께 수정해 기준선이 흔들렸는지 확인한다.
3. **에러 무시로 얻은 속도(Fast Failure Masking)**: 요청 실패, 파싱 생략, 조기 빈 반환으로 작업량이 줄어든 것을 속도 향상으로 착각했는지 에러 카운트 0 여부로 대조한다.
4. **콜드/웜 캐시 혼동(Cache State Drift)**: 변경 전은 콜드 상태, 변경 후는 OS/런타임 캐시가 데워진 상태에서 측정했는지 교차 반복 실행으로 확인한다.
5. **표본 부족 및 노이즈 미분리(Sub-Noise Win)**: 측정 분산(표준편차 또는 최소/최대 폭) 이내의 미세 변동을 개선으로 채택했는지 최소 3회 이상 반복 수치로 확인한다.
6. **측정 외 경로 병목(Wrong Limiter)**: 최적화한 함수가 전체 실행 시간의 지배적 병목이 아닌데 부분 마이크로벤치마크 수치만 보고 전체 개선으로 주장했는지 확인한다.
7. **자기 보고 의존(Self-Report Proxy)**: 실제 산출물이나 외부 프로세스 상태를 읽지 않고 로그 출력 문구나 종료 코드만으로 성공을 단정했는지 확인한다.
8. **부분 회귀 은폐(Selective Metric Cherry-Picking)**: 목표 지표 1개는 개선되었으나 메모리 사용량, 지연 꼬리값(p99), 정확도 중 다른 핵심 지표가 악화되었는지 함께 확인한다.
