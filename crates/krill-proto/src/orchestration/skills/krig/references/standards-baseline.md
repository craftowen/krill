# 코딩 표준 및 코드 스멜 기준선 (Standards Baseline)

이 문서는 구현 에이전트의 컨텍스트 압박을 막기 위해 구현 단계에서는 읽지 않고, 오직 [verify.md](../playbooks/verify.md)의 **Standards 리뷰 서브에이전트**만 읽는다.

## 1. 구조 및 경계 불변 조건

1. **경계 검증 집중**: 외부 입력(CLI 인자, 환경변수, 파일 파싱, HTTP/웹훅 페이로드)은 진입 경계에서 한 번만 파싱해 타입이 좁혀진 데이터로 변환한다. 내부 함수 체인 깊숙한 곳에서 중복 null/타입 방어 코드를 반복하지 않는다.
2. **도메인 구조화**: 여러 파일에 반복되는 `if/else` 분기 사슬이나 서로 동기화해야 하는 불리언 플래그 쌍(`isLoading` + `isDone` 등)은 명시적 상태 머신이나 레지스트리 테이블로 치환되었는지 확인한다.
3. **멱등성 보장**: 재시도나 중간 재시작이 가능한 명령, 설치 스크립트, 상태 기록 함수는 두 번 연속 실행해도 동일한 최종 상태로 수렴하는지 확인한다.

## 2. Fowler 코드 스멜 12종 점검표

변경된 diff에서 아래 12가지 스멜이 새로 유입되었는지 파일과 줄 번호로만 지적한다.

1. **Duplicated Logic**: 동일 도메인 규칙이 두 곳 이상에 복제되어 한쪽만 수정될 위험이 있는 코드.
2. **Long Parameter List**: 4개 이상의 느슨한 위치 인자를 넘기며 데이터 구조가 묶이지 않은 시그니처.
3. **Divergent Change**: 하나의 모듈이 서로 다른 이유(파싱, 비즈니스 규칙, 저장소 입출력)로 동시에 수정되는 구조.
4. **Shotgun Surgery**: 단일 정책 변경을 위해 여러 파일의 분기문을 동시에 고쳐야 하는 산재된 결합.
5. **Feature Envy**: 자신이 속한 모듈보다 다른 모듈의 내부 필드를 반복 조회해 계산하는 함수.
6. **Data Clumps**: 항상 함께 몰려다니지만 이름 붙은 타입이나 객체로 묶이지 않은 필드 묶음.
7. **Primitive Obsession**: 상태 코드, 식별자, 단위 있는 수치를 검증 없는 원시 문자열/숫자로 흘려보내는 코드.
8. **Speculative Generality**: 현재 호출자가 쓰지 않는 옵션 플래그, 훅, 추상 베이스 클래스.
9. **Middle Man**: 실질적 변환이나 불변 조건 보장 없이 다른 함수를 그대로 위임만 하는 얕은 래퍼.
10. **Mutable Shared State**: 동시 실행 주체나 루프 단계가 같은 가변 객체/파일을 격리 없이 덮어쓰는 지점.
11. **Comments Explaining What**: 코드가 이미 보여주는 동작이나 단계(`// Step 1`)를 서술하는 불필요한 주석(비자명한 이유 설명만 허용).
12. **Implementation-Pinned Tests**: 사용자 관측 행동이 아니라 내부 헬퍼 호출 여부나 구현 상수를 복제해 단언하는 테스트.
