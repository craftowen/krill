# Recon Playbook (코드 구조 이해, 의사결정 계보, 변경 영향도 증명)

## Trigger

코드를 직접 수정하지 않고 서브시스템의 동작 원리를 파악(`how`)하거나, 특정 코드와 상수가 왜 현재 구조로 만들어졌는지 계보를 추적(`why`)하거나, 변경 전 파급 범위를 증명(`blast`)해야 할 때 `afk` 기어로 실행한다. 영향도 조사와 실제 수정이 함께 요청된 경우에는 이 플레이북으로 안전 제약을 먼저 확정한 뒤 [drive.md](drive.md)로 넘긴다.

## Steps

1. **결정론적 앵커 추출.** 추측으로 파일을 훑기 전에 [recon.mjs](../scripts/recon.mjs)로 대상 심볼 또는 경로의 정의 위치, 프로덕션 및 테스트 호출부, 모듈 임포터, 외부 경계 표면(`env`, `cli`, `subprocess`, `filesystem`, `network`), git 커밋 및 픽액스(`git log -S`) 이력을 수집한다.

```bash
node "<SKILL_DIR>/scripts/recon.mjs" --json --repo "$PWD" --symbol "<심볼명>"
# 특정 파일이나 하위 디렉터리만 좁혀 분석할 때만 --path 추가:
node "<SKILL_DIR>/scripts/recon.mjs" --json --repo "$PWD" --path "<하위경로>"
```

2. **세부 조사 모드별 수행 (`route.mjs`의 `reconMode` 기준).**
   - **`how` 모드 (동작 원리 및 멘탈 모델)**:
     1. 진입점부터 핵심 데이터 변환, 상태 저장소, 외부 출력 경계까지 실제 제어 흐름을 `파일:줄` 단위로 추적한다.
     2. 서브시스템이 넓은 경우 읽기 전용 서브에이전트(`agy`는 `TypeName: "research"`, `Model: "inherit"`)로 계층별 탐색을 병렬 수행하고 메인 컨텍스트에서 단일 멘탈 모델로 합성한다.
   - **`why` 모드 (의사결정 계보 및 제약 추출)**:
     1. `recon.mjs`가 추출한 픽액스 커밋과 `git show <SHA>` 및 `git log -L <시작>,<끝>:<파일>` 본문을 대조해 해당 코드가 해결하려던 원래 문제와 당시 제약 조건을 복원한다.
     2. 모든 진술을 커밋이나 테스트로 입증된 **확인된 사실**, 정황에서 도출한 **추론**, 저장소 밖 맥락이라 알 수 없는 **미확인** 3단계로 엄격히 분리한다.
     3. 향후 수정자를 위해 반드시 지켜야 할 불변 제약(`Preserve`), 안전하게 바꿀 수 있는 영역(`Safe to Change`), 과거에 실패했거나 피해야 할 함정(`Avoid`), 숨은 결합 위험(`Hidden Risk`) 4항목으로 결론을 정리한다.
   - **`blast` 모드 (5단계 영향도 사다리 증명)**:
     1. `L1 어휘/정의`, `L2 호출부 및 임포터`, `L3 외부 경계 계약`(CLI 플래그, JSON 출력 스키마, DB 컬럼, 환경변수, 플러그인 매니페스트)을 `recon.mjs` 출력으로 전수 확인한다.
     2. 단순히 호출부 목록을 나열하는 데 그치지 않고, 변경이 안전하려면 반드시 성립해야 하는 **단 하나의 핵심 안전 명제(load-bearing safety fact)**를 특정한다.
     3. `L4 런타임 프로브` 또는 `L5 실행 증명`(짧은 읽기 전용 검증 명령이나 비파괴 입력 실행)을 직접 돌려 그 안전 명제가 실제로 참인지 입증한다.

## Rules

- 단독 `recon` 실행에서는 저장소의 추적 중인 소스 파일이나 설정 파일을 수정하지 않는다.
- 커밋 메시지에 적히지 않은 과거 의도를 단정 어조로 지어내지 않고 반드시 `추론` 또는 `미확인`으로 표기한다.
- 영향도 보고 시 테스트 호출부와 실제 프로덕션 호출부를 섞어 건수를 부풀리지 않고 분리해 보고한다.

## Verification

- `recon.mjs` 종료 코드 `0`과 추출된 정의 및 호출부 `파일:줄`이 실제 현재 작업 트리의 라인 번호와 일치하는지 확인한다.
- `blast` 모드에서는 핵심 안전 명제를 확인한 실제 프로브 명령과 관측 출력을 근거로 남긴다.
